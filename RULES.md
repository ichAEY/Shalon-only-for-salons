# Правила Salon Engine

## Источник данных

Используются только подтверждённые сведения салона. Нельзя придумывать цены, длительность, услуги, опыт специалистов, отзывы, контакты или режим работы.

Если информации нет, поле остаётся пустым. Нейтральная заглушка в базовом репозитории нужна только для проверки композиции.

## Что разрешено менять для нового салона

Обычно меняются только:

- `site-data.mjs`;
- клиентские файлы внутри `public/`;
- `CNAME`, если подключается собственный домен;
- `NEXT_PUBLIC_BASE_PATH` в workflow, если сайт остаётся на стандартном адресе GitHub Pages.

Общий компонент, CSS и тесты под отдельного клиента не переделываются.

## Медиа

- Фотографии загружаются в WebP или AVIF, если прозрачность не нужна.
- PNG используется для логотипов и изображений с прозрачностью.
- Главная фотография должна быть пригодна для вертикального mobile-кадра и широкого desktop-кадра.
- Видео должно быть оптимизировано заранее; в шаблоне оно загружается с `preload="metadata"`.
- В `alt` указывается фактическое содержание фотографии, без рекламных фраз.

## Услуги

- Категорий может быть сколько угодно.
- У каждой категории — уникальный `id`.
- У услуги обязательно есть подтверждённое название.
- Цена, длительность, описание и отдельная ссылка записи добавляются только когда известны.
- Ссылка конкретной услуги имеет приоритет над общей ссылкой записи.

## Запись и контакты

- При наличии `links.bookingUrl` кнопки ведут на прямую запись.
- Без прямой записи открывается окно проверенных контактов.
- Телефон сам по себе является полноценным способом записи.
- Instagram не публикуется и блокируется валидатором.

## Команда

- У каждого специалиста должен быть уникальный `id` и имя.
- Роль, описание, фотография и категории добавляются только по подтверждённым данным.
- Количество специалистов не зафиксировано: mobile использует горизонтальную ленту, desktop — сетку.

## Отзывы

- Не больше девяти проверенных отзывов.
- Автор, источник и текст сохраняются точно, без пересказа и дописывания.
- Если отзывов нет, при создании клиентского сайта раздел следует скрыть отдельным общим правилом, а не заполнять выдуманными текстами.

## Языки

- Для России базовый порядок: RU, EN.
- Для другой страны: местный язык, RU, EN.
- Клиентские тексты переводятся через `i18n.translations`.
- Валидатор не пропустит заполненный сайт с отсутствующими переводами заявленных языков.

## Производительность

- Не добавлять `MutationObserver`, циклический `requestAnimationFrame` или периодическую перерисовку интерфейса.
- Не вставлять CSS и HTML через JavaScript.
- Не создавать файлы `final-v2`, `fix-v3` и аналогичные слои исправлений.
- Общая ошибка исправляется один раз в Salon Engine, после чего прогоняются все проверки.
