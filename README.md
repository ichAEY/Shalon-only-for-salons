# Salon Template

Готовый универсальный шаблон TANEM для салонов.

## Структура
- `index.html` — базовая разметка и выбор mobile/desktop runtime.
- `mobile.js` — единый мобильный runtime: portrait, landscape-phone, галерея, услуги, команда, отзывы, запись, медиа и языки.
- `desktop.js` — единый desktop/MacBook runtime и один итоговый stylesheet.
- `logo-placeholder.svg` — заглушка логотипа.
- `media-placeholder.svg` — заглушка фото/медиа.

Промежуточные версии, fix/patch-файлы и старые загрузчики удалены. При создании сайта нового салона меняются только данные и медиа; геометрия, адаптивность и механики шаблона остаются без изменений.


## Правила заполнения салона
- Языки выбираются по стране салона: для России — только `RU / EN`; для Армении — `RU / EN / HY`. Армянский язык нельзя автоматически добавлять российским салонам.
- Статус работы и город в hero должны использовать одну компактную визуальную механику на mobile и desktop.
- Если у салона есть видео, его можно использовать первым элементом портфолио/галереи вместо hero; hero-медиа задаётся отдельно из салонных фотографий.
- Если в команде больше четырёх подтверждённых мастеров, desktop показывает четыре карточки одновременно, остальные доступны горизонтальным перелистыванием с явными элементами управления.
- Имена, должности, рейтинг, количество отзывов, услуги, цены и контакты нельзя придумывать. Используются только подтверждённые данные.
- Рейтинг отображается с заполненной жёлтой звездой/звёздами. В счётчике отзывов показывается подтверждённое количество отзывов; отдельное количество оценок не выводится, если оно не требуется.
- Лента отзывов должна быть бесконечной и бесшовной.
- Изменения конкретного салона встраиваются в основные данные и компоненты шаблона; запрещено накапливать в конце файлов runtime-патчи, которые после загрузки переписывают уже созданный интерфейс.
- Логотип/знак, если нужен отдельно от полного логотипа, хранится отдельным подготовленным asset; нельзя имитировать его грубой CSS-обрезкой полного изображения.
- Медиа-элементы портфолио и галереи должны быть типизированы как фото/видео, чтобы видео не попадало в просмотрщик изображений.
- Бесконечная лента отзывов строится из итогового массива подтверждённых отзывов до измерения/запуска анимации; обе копии ленты должны быть идентичными.
- Для desktop-команды при количестве мастеров больше четырёх сохраняется постраничная структура: первая страница — 4 мастера, следующая — остаток; перелистывание работает и кликом по деликатной боковой подсказке, и drag/swipe. Геометрия аватаров на всех страницах должна быть одинаковой, круги не растягиваются, неполная последняя страница начинается сверху.
- На mobile горизонтальная лента команды может визуально доходить до физических краёв экрана; внутренние отступы сохраняют исходное положение первой карточки, но соседние карточки нельзя обрезать искусственным внутренним viewport.
- В mobile-услугах при переносе desktop-механики строка остаётся компактной: название + цена; не дублировать текст «Записаться» и стрелки. Цена оформляется адаптированной desktop-плашкой с тем же индикатором/пульсацией.
- Фото и видео открываются в одном media viewer. Счётчик viewer рассчитывается по полному уникальному набору медиа галереи, а не только по превью портфолио; видео должно открываться и перелистываться наравне с фотографиями.
- Статус в hero рассчитывается по локальному времени салона: «Открыто» выделяется зелёным, «Закрыто» — красным; рядом показываются часы работы без лишнего слова «Ежедневно», если дизайн hero использует компактный формат.
